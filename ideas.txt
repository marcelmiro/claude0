## Session Inbox (SHIPPED — ADR 0013; upgrade ideas below still open)
Lifecycle model locked 2026-08-02 (see docs/adr/0013 + CONTEXT.md terms). Phase 1 = model + Mac CLI verbs + tmux sidebar prototype; Phase 2 = portkey Inbox UI. Upgrade-path ideas deferred during the grilling, to revisit AFTER living with v1:

## Post-hoc Re-flag (mark session as needs-attention) — SUPERSEDED by Session Inbox
- Problem: once ⚡ clears on focus, a session that's STILL `waiting` never re-flags — the monitor flags on the running→waiting *transition*, not on standing state. So a glanced-at-but-deferred block loses its ⚡ for the rest of its life.
- The inbox disposal invariant (ADR 0013) dissolves this: Needs you membership never clears on focus/glance — only reply, park, or archive dispose. No manual re-flag needed; the flag can't vanish in the first place.
- (Original 2026-07 sketch: a key to set `needsAttention` back on. Kept for reference; don't build.)

## Instant Prefix Updates via Claude Hooks
- Use Claude Code hooks (UserPromptSubmit, Stop, Notification) to update ⚡/🔄 window prefixes instantly instead of waiting for poll cycle
- UserPromptSubmit → add 🔄, Notification(permission_prompt) → add ⚡, Stop → add ⚡ or clear
- Hook scripts are ~4 lines each (just tmux rename-window), no state.json interaction needed
- Complements existing polling: hooks for speed, monitor for consistency (redundant renames are harmless)
- `c0 setup-hooks` subcommand to auto-write hook config into ~/.claude/settings.json

## Per-question custom answer on the phone ("Type something.")
- Mirror the native AskUserQuestion widget's "Type something." row: a per-question free-text field on the bridge QuestionCard whose text becomes THAT question's answer (labels still tappable for the others).
- Mechanism (verified 2026-07-18): rides the existing answer channel — `updatedInput.answers[<question text>] = <free text>`. Arbitrary non-label strings are accepted and received by the agent verbatim; mixable with label answers across a multi-question prompt.
- Impl sketch: let `/answer` accept a string entry in the per-question selections array (alongside number / number[]); `buildAnswersMap` passes a string straight through.
- Deferred in favor of the global "Chat about this" (decline→clarify→chat) flow, which covers redirect/clarify/dislike-options via a real conversation. This is the narrower one-shot-custom-answer case — additive later.
